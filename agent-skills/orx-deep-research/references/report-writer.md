# Writing the research report

Read every completed notes file in the assigned request folder, the attribution
manifest, and any earlier report/notes explicitly provided. Do not read earlier
work for an independent redo. Quote paths containing spaces. Missing files are
missing evidence, not permission to invent findings or start new research.

Write a self-contained report answering the entire user question. New notes
supersede older material only where the source quality, relevance or dates
justify it; do not automatically treat a newer note as more authoritative.
Explain substantive conflicts and preserve uncertainty. Prefer five supported
claims over twenty weakly sourced ones.

## Structure

Use a concise title in the user's language, normally matching the assigned
report title. Open with the key finding and its significance in one compact
paragraph. Then write approximately 3–5 sections with informative sentence-case
headings that communicate insights rather than generic categories. Develop an
argument through connected narrative paragraphs, highlighting only the most
important facts. Use a table when it materially improves comparison; avoid
turning the report into a list of unrelated findings. End with implications
and unresolved decisions rather than repeating the opening.

Scale depth to the question and requested length. An engineering decision needs
precise tradeoffs and practical limits; a scientific review needs methods,
contradictory evidence and uncertainty. Do not remove qualifiers when the
source only supports a tentative conclusion. Distinguish findings, your
synthesis and proposals for future experiments.

## Citations and reproducibility

Cite key claims, quantities and references inline as `([Source](URL))` using the
original URLs in the notes. Each link must support its adjacent claim. Verify
citations against the supplied notes; do not add plausible-looking references
or present summaries of inaccessible originals as direct readings. Omit
unsupported major claims or explain the evidence gap explicitly.

For project measurements, cite the recorded run, commit and log/artifact paths.
Keep comparisons on matching dataset revisions/splits and report seed counts
and variability when available. Never turn missing measurements into zero,
model agreement into independent empirical evidence, or compute estimates
into billed costs. Use relative links for notes and figures stored beside the
report so the artifact remains portable.

Add a brief provenance paragraph stating research date, important scope limits,
and actual harness/model contributions supplied in the manifest. If only one
harness worked, say so. Do not invent attribution or imply human peer review.

## Delivery

Save only to the assigned absolute new report path. Do not rename or overwrite
previous reports, edit experiment branches, publish to GitHub/Overleaf, or send
messages externally. Confirm the report is present and its local links resolve.
Return the exact path, key finding and material caveats to the coordinator.
